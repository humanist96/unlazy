# checks: 업무 산출물 검증기

게이트의 `CHECK:` 자리에 그대로 넣어 쓰는 검증 명령 모음이다. 코드가 아닌 산출물,
곧 보고서·데이터·배치 로그를 대상으로 한다.

의존성이 없고 Node 16 이상이면 동작한다. 외부 패키지를 받지 않으므로 폐쇄망에
반입한 뒤에도 그대로 쓸 수 있다.

## 왜 필요한가

게이트는 명령이 종료 코드 0을 내고 `EXPECT:` 문자열이 출력에 나타날 때만 충족된다.
검증할 명령이 없으면 남는 선택지는 수동 게이트뿐인데, 수동 게이트의 증거는 읽은
사람의 성실성만큼만 믿을 수 있다. 이 디렉터리는 사무 업무에서 반복되는 확인
항목을 실행 가능한 명령으로 바꿔 그 간격을 메운다.

## 검증기

| 검증기 | 대상 | 대표 확인 항목 |
|---|---|---|
| `check-file.mjs` | 모든 파일 | 존재, 최소 크기, SHA-256, 생성 시각(오늘 산출물인지) |
| `check-encoding.mjs` | 텍스트 파일 여러 개 | UTF-8/CP949 판별, BOM, 문자 깨짐, 파일 간 인코딩 일관성 |
| `check-csv.mjs` | CSV | 필수 컬럼, 행 수, 중복·공백 키, 합계 대사(두 파일 독립 측정) |
| `check-docx.mjs` | Word 보고서 | 필수 절 존재, 분량, 표 개수, 자리표시자 잔존 |
| `check-xlsx.mjs` | Excel 산출물 | 시트 존재, 특정 셀 값, `#REF!` 등 오류 셀, 자리표시자 |
| `check-batch-log.mjs` | 배치 로그 | 완료 배너 존재, 오류 문자열 부재(양성 대조 강제), 로그 신선도 |

각 검증기의 전체 옵션은 `--help`로 확인한다.

```bash
node <skill-dir>/checks/check-csv.mjs --help
```

## 공통 계약

모든 검증기가 동일하게 지킨다.

- **성공 표지**: 모든 단언을 통과한 경우에만 `UNLAZY-CHECK-OK <검증기 이름>: <측정값>`
  을 출력한다. 실패 경로에서는 이 문자열이 절대 나오지 않는다. 그래서 `EXPECT:`에는
  `UNLAZY-CHECK-OK check-csv`처럼 검증기 이름까지 적는 것이 안전하다.
- **종료 코드**: `0` 통과, `1` 측정된 실패, `2` 사용법 오류이거나 입력을 읽을 수 없음.
  종료 코드 2는 "검증하지 못했다"는 뜻이지 "통과"가 아니다.
- **표지 위조 방지**: 검증기는 남이 만든 파일을 읽는다. CSV 셀이나 로그 줄에
  `UNLAZY-CHECK-OK`가 들어 있어도 실패 진단에 그대로 실려 나가지 않도록, 실패
  출력에서는 그 문자열을 가려서 찍는다.
- **측정값 보고**: 성공 요약에 실제로 센 값을 적는다. 행 수, 단어 수, 합계 같은
  값이 원장의 EVIDENCE에 남아야 나중에 무엇이 확인됐는지 알 수 있다.
- **한국어 입력**: 파일 경로, 컬럼명, 시트명, 검색어에 한글을 쓸 수 있다. CP949로
  저장된 CSV와 로그는 자동 판별하며 `--encoding cp949`로 강제할 수도 있다.

## 부재 검사에는 양성 대조가 필요하다

"오류가 없다", "자리표시자가 남아 있지 않다" 같은 주장은 부재 검사다. 부재 검사는
탐지기가 고장 났을 때도, 경로가 틀려 엉뚱한 파일을 읽었을 때도, 대상이 비어
있을 때도 똑같이 통과한다. 통과했다는 사실만으로는 아무것도 증명되지 않는다.

그래서 두 가지 장치를 둔다.

`check-batch-log.mjs`는 이 규칙을 기계적으로 강제한다. `--forbid-pattern`을 쓰면서
`--positive-control`을 주지 않으면 종료 코드 2로 거부한다. 양성 대조 패턴은 로그가
실제로 읽혔고 올바르게 디코딩됐음을 증명하는 역할을 한다.

```bash
node <skill-dir>/checks/check-batch-log.mjs "로그/야간배치.log" \
  --positive-control "배치 시작" \
  --require-pattern "정상 종료" \
  --forbid-pattern "ERROR|FATAL|오류"
```

나머지 검증기의 부재 옵션(`--no-placeholders`, `--no-error-cells`, `--forbid-text`)은
강제할 방법이 없으므로 규율로 남는다. 자리표시자나 오류 셀이 확실히 들어 있는 사본을
한 번 만들어 같은 명령이 실패하는 것을 확인하고, 그 결과를 별도 수동 게이트의
EVIDENCE에 적는다. 한국어 템플릿 두 개가 이 수동 게이트를 미리 넣어 두었다.

## 게이트 템플릿

- `templates/gates-report-ko.md` : 보고서 산출물 검증
- `templates/gates-recon-ko.md` : 데이터 대사 검증

복사해서 `GATES.md`로 쓰고 자리표시자를 채운다.

두 템플릿을 `gate-lint.mjs`로 검사하면 양성 대조용 수동 게이트에 대해 경고 두
종류가 나온다. 둘 다 의도한 결과다.

- `manual-gate` : 수동 게이트라는 사실 자체에 대한 경고. 양성 대조는 사람이 눈으로
  확인해야 하므로 수동일 수밖에 없다.
- `unmeasured-number` : 제목에 숫자가 있는데 측정하는 명령이 없다는 경고. 실제로는
  "G3의", "R5의"처럼 다른 게이트 번호를 가리키는 표현을 린터가 숫자로 읽은 것이다.

이 두 경고 때문에 `--strict`를 걸면 원장이 실패한다. 자기 품질을 게이트로 거는
경우에는 `--strict` 없이 쓰거나, 양성 대조 게이트를 별도 파일로 분리한다.

## Windows 사용 시 주의

- **원장 파일은 UTF-8(BOM 없음)로 저장한다.** `GATES.md`를 CP949로 저장하면 파서가
  한국어 게이트 제목을 깨뜨린다. 검증 대상 파일의 인코딩과는 별개 문제다.
- **`EXPECT:`는 ASCII로 쓴다.** 기본 셸이 `cmd.exe`이고 콘솔 코드 페이지가 CP949라서
  한국어 EXPECT는 바이트가 어긋나 매칭에 실패할 수 있다. 성공 표지가 ASCII인 이유다.
- **공백이 있는 경로는 큰따옴표로 감싼다.** `cmd.exe`에서 작은따옴표는 인용부호가
  아니다.
- **`--reverify`로 반복 점검을 만든다.** 매일 다시 참이어야 하는 항목은 원장을
  상시 유지하고 작업 스케줄러에서 `gate-check.mjs --reverify`를 돌린다. 이때
  실행 계정과 PATH가 승인 시점과 같아야 재승인 요구가 반복되지 않는다.

## 검증기가 증명하지 못하는 것

각 검증기의 헤더 주석에 항목별로 적어 두었으나, 공통된 한계는 다음과 같다.

- 형식과 존재를 확인할 뿐 **내용의 품질**은 판단하지 못한다. 요구한 절이 있다는
  것과 그 절이 쓸 만하다는 것은 다른 문제다.
- `check-xlsx.mjs`는 **저장된 셀 값**을 읽는다. 재계산되지 않은 통합 문서는 Excel이
  마지막으로 쓴 값을 그대로 보고하며, 수식 자체의 타당성은 검증하지 않는다.
- 인코딩 판별은 **추정**이다. 순수 ASCII 파일은 UTF-8이면서 동시에 CP949이므로
  바이트만 보고는 구분할 수 없다.
- `check-file.mjs`의 수정 시각은 복사와 동기화로도 갱신되므로, 오래된 파일이
  아니라는 것은 말해 주지만 누가 만들었는지는 말해 주지 않는다.

## 테스트

```bash
node <skill-dir>/checks/tests/lib-tests.mjs
node <skill-dir>/checks/tests/checker-tests.mjs
```

`checker-tests.mjs`는 각 검증기를 실제 하위 프로세스로 실행하며, 부재 검사마다
통과 사례와 양성 대조(반드시 실패해야 하는 사례)를 짝지어 확인한다.
