# 감사 자료 익스포트

`scripts/export-audit.mjs`는 unlazy가 남긴 기록을 모아 감사·컴플라이언스에 제출할
수 있는 형태로 묶는다. 읽기 전용이며 `CHECK:`를 실행하지 않고 원장도 수정하지
않는다.

## 왜 필요한가

규제 환경의 질문은 개발자의 질문과 다르다. "통과했는가"가 아니라 "누가 무엇을
근거로 수락했고, 그 기록이 이후에 수정되지 않았음을 보이라"이다.

unlazy는 그 재료를 이미 전부 기록하고 있다. 다만 세 곳에 흩어져 있고 그중 둘은
저장소 밖에 있다.

| 재료 | 위치 |
|---|---|
| 게이트 상태와 증거 | 원장(`GATES.md`, `.unlazy/<scope>/**/*.md`) |
| 무엇을 승인했는지와 시각 | 승인 저장소(`~/.unlazy/approved`) |
| 이벤트 추가 기록 | 상태 로그(`status.log`) |
| 병렬 실행 이력 | `dispatch.json` |

이 도구는 넷을 한 파일로 묶고, 각 원본의 SHA-256을 매니페스트로 남겨 자료 생성
이후의 변조를 탐지할 수 있게 한다.

## 사용법

```bash
node <skill-dir>/scripts/export-audit.mjs --format md GATES.md --actor "사번12345 홍길동" --out 감사자료.md
```

주요 옵션.

| 옵션 | 설명 |
|---|---|
| `--format md\|json\|csv` | 기본 `md`. 제출용은 `md`, 보관용은 `json`, 엑셀 취합은 `csv` |
| `--out FILE` | 파일로 저장(생략 시 표준 출력) |
| `--scope ID` | `.unlazy/<ID>` 파이프라인 전체(하위 원장, 로그, 디스패치 포함) |
| `--actor NAME` | 자료 생성 계정. 환경변수 `UNLAZY_ACTOR`로도 지정 |
| `--approval-dir DIR` | 승인 저장소 위치 |
| `--include-path` | 승인에 묶인 PATH 전문을 포함(기본은 지문만) |
| `--no-bom` | CSV에서 UTF-8 BOM 생략 |

CSV는 기본으로 UTF-8 BOM을 붙인다. 한글 Windows의 엑셀은 BOM 없는 UTF-8 CSV를
CP949로 읽어 한글을 깨뜨리기 때문이다. 사내 텍스트 표준은 BOM 없음이므로
`check-encoding.mjs --no-bom`은 이 파일을 지적하는데, 이 산출물에 한해서는 정상이다.

종료 코드는 익스포트 성공 여부만 나타낸다(0 성공, 2 사용법 오류·입력 없음).
게이트 통과 여부는 종료 코드가 아니라 보고서 안의 지적 사항으로 확인한다.

## 지적 사항 코드

| 코드 | 심각도 | 의미와 대응 |
|---|---|---|
| `abandoned` | 높음 | 게이트가 포기 선언됨. 사유를 확인하고 인계 여부를 결정한다 |
| `checked-without-evidence` | 높음 | 체크박스는 켜졌으나 증거가 없다. 체커가 쓰지 않은 손편집일 수 있으므로 `--reverify`로 재실행한다 |
| `ledger-parse-error` | 높음 | 원장이 형식을 위반했다. 이 상태에서는 어떤 완료 주장도 성립하지 않는다 |
| `met-without-standing-approval` | 보통 | 통과 기록은 있으나 대응 승인 레코드가 없다. 승인이 삭제됐거나 승인 이후 명령·경로·셸·PATH가 바뀐 경우다. `--reverify`로 현재도 통과하는지 확인한다 |
| `manual-met` | 보통 | 수동 게이트가 충족으로 기록됐다. 증거의 신뢰도는 검토자에게 달려 있으므로 검토 기록을 함께 보관한다 |
| `unmet` | 보통 | 미충족 |
| `dispatch-*` | 보통/높음 | 발사 웨이브가 완료되지 않았다 |
| `orphan-approval` | 낮음 | 승인이 가리키는 원장이 없다. 정리 대상 |

## 알려진 한계

보고서 말미에 같은 내용이 실리므로 감사자가 함께 읽게 된다. 미리 알아 둘 것.

- **검증 시각은 로컬 시계다.** 각 게이트의 `verified-at`은 검증이 끝난 시점을 그
  머신의 시계로 읽은 값이다. 시계가 틀렸거나 표준시와 어긋나 있으면 그대로 어긋난
  값이 남는다. 순서와 날짜는 알려주지만 시각을 증명하지는 않는다. 이 필드가 없는
  항목은 그 이전에 기록된 증거다.
- **승인에 사용자 필드가 없다.** 승인 레코드는 시각과 묶인 오라클만 담는다. 보고서의
  생성 계정은 자료를 뽑은 계정이지 각 게이트를 검토한 사람이 아니다. 이것도 상류
  개선 후보다.
- **승인은 호출 스크립트를 해싱하지 않는다.** 명령 텍스트가 같으면 그 명령이
  실행하는 파일이 바뀌어도 기존 승인이 유효하다. 당장의 완화책은 기대 다이제스트를
  `CHECK:` 문장 안에 직접 넣어 승인 서명에 포함시키는 것이다.
- **Windows에서 승인 저장소 권한이 검증되지 않는다.** 엔진이 소유자·권한 검사를
  win32에서 건너뛰므로 NTFS ACL에 의존한다. 이 도구는 ACL을 확인하지 않는다.
- **변조 방지가 아니라 변조 탐지다.** 번들 다이제스트는 자료를 다시 생성하면 함께
  바뀐다. 원본 보관은 별도 절차가 필요하다.

## 정기 점검과 함께 쓰기

`gate-check.mjs --reverify`를 스케줄러로 돌리는 반복 점검(예: 일일 시스템 점검,
데이터 대사)에서는 재검증 직후 익스포트를 한 번 더 돌려 그날의 자료를 남긴다.

```bash
node <skill-dir>/scripts/gate-check.mjs --reverify GATES.md
node <skill-dir>/scripts/export-audit.mjs --format json GATES.md --out 보관/감사_2026-03-05.json
```

재검증이 실패하면 원장의 체크박스가 해제되므로, 그 상태로 뽑은 자료가 곧 "언제부터
무엇이 깨졌는가"의 기록이 된다.
