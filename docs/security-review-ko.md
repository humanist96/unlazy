# unlazy 사내 보안 검토 답변서

작성 목적: 이 도구를 사내에 반입하기 위한 보안 검토 질의에 대한 답변. 모든 주장에는
검토자가 직접 재현할 수 있는 확인 방법을 함께 적었다. 확인하지 않은 항목은 확인하지
않았다고 적었다.

기준 버전: `2.1.0` 계열 포크. 상세 위협 모델 원문은 저장소의 `SECURITY.md`에 있으며
이 문서는 그것을 사내 검토 항목 순서로 옮기고 실증을 덧붙인 것이다.

## 1. 도구 개요

AI 코딩 에이전트가 작업을 절반만 하고 "완료"라고 보고하는 문제를 막는 규율 도구다.
작업 전에 수락 기준을 `GATES.md`라는 원장에 적고, 각 기준마다 **검증 명령**을 선언한
뒤, 그 명령이 종료 코드 0으로 끝나고 기대 문자열을 출력해야만 충족으로 인정한다.

핵심적으로 이해할 점: **이 도구 자체는 업무 로직을 수행하지 않는다.** 사용자가 적은
검증 명령을 사용자가 승인했을 때 실행하고 그 결과를 기록할 뿐이다. 보안 관점의 실질
질문은 "이 도구가 무엇을 하는가"가 아니라 "사용자가 승인한 명령이 실행되는 경로가
통제되는가"이다.

## 2. 반입 대상과 공급망

| 항목 | 내용 |
|---|---|
| 구성 | Node.js 스크립트와 Markdown 문서뿐. 컴파일된 바이너리 없음 |
| 런타임 외부 의존성 | **0개**. `package.json`에 `dependencies` 항목 자체가 없음 |
| 설치 방식 | 저장소 파일 복사. `npm install` 단계 없음 |
| 실행 요건 | Node.js 16 이상 |

의존성이 0이므로 공급망 심사 대상은 반입되는 저장소 파일 그 자체로 한정된다. 외부
패키지 레지스트리를 실행 시점에 조회하지 않는다.

확인 방법:

```bash
grep -E '"dependencies"|"devDependencies"' package.json   # 출력 없음
ls node_modules                                            # 존재하지 않음
npm test                                                   # 오프라인에서 전량 통과
```

`npm test`는 외부 네트워크 없이 완결되므로, 폐쇄망 반입 후 무결성 확인 절차로 그대로
쓸 수 있다.

## 3. 명령 실행 경계 (핵심 항목)

### 3.1 실행되는 경로는 하나뿐이다

검증 명령이 실제로 실행되는 유일한 경로는 사용자가 `--approve`를 명시적으로 붙여
실행했을 때다. 그 외 모든 진입점은 명령을 읽고 보여줄 뿐 실행하지 않는다.

프로세스를 생성할 수 있는 코드는 배포 파일 중 정확히 세 개다.

| 파일 | 역할 |
|---|---|
| `scripts/gate-check.mjs` | 승인된 검증 명령을 감독 프로세스를 통해 실행 |
| `scripts/lib/check-supervisor.mjs` | 셸을 통해 실제 명령을 실행하는 중개 계층 |
| `scripts/lib/process-tree.mjs` | 타임아웃 시 Windows `taskkill`로 프로세스 트리 정리 |

나머지는 전부 프로세스를 생성하지 않는다. 특히 **Stop 훅과 문서·데이터 검증기
6종은 아무것도 실행하지 않는다.**

확인 방법:

```bash
grep -rn "child_process" scripts/ checks/ | grep -v tests
```

### 3.2 재현 가능한 실증

흔적 파일을 남기는 명령을 원장에 넣고 각 진입점을 실행해, 실제로 실행되지 않음을
확인할 수 있다.

```bash
mkdir 실증 && cd 실증
cat > GATES.md <<'EOF'
# Gates: 실행 경계 실증

- [ ] G1: 이 명령이 실행되면 흔적 파일이 생긴다
  CHECK: node -e "require('fs').writeFileSync('EXECUTED.txt','ran')"
  EXPECT: never matched
  EVIDENCE: pending
EOF

node <skill-dir>/scripts/gate-check.mjs --status GATES.md ; ls EXECUTED.txt   # 없음
node <skill-dir>/scripts/gate-check.mjs GATES.md         ; ls EXECUTED.txt   # 없음
node <skill-dir>/scripts/gate-lint.mjs GATES.md          ; ls EXECUTED.txt   # 없음
node <skill-dir>/scripts/export-audit.mjs GATES.md       ; ls EXECUTED.txt   # 없음
```

이 결과가 의미를 가지려면 그 명령이 애초에 흔적을 남길 수 있어야 한다. 양성 대조로
확인한다.

```bash
node <skill-dir>/scripts/gate-check.mjs --approve GATES.md ; ls EXECUTED.txt  # 생성됨
```

양성 대조까지 확인해야 앞의 "흔적 없음"이 탐지 실패가 아니라 실제 미실행임이 증명된다.

### 3.3 승인이 묶는 대상

승인은 명령 문자열 하나가 아니라 실행 문맥 전체에 묶인다.

명령 텍스트, 기대 문자열, 해석된 작업 디렉터리, 해석된 셸의 절대경로, 타임아웃,
출력·정규식 한도, 플랫폼, 그리고 상속된 `PATH` 전문. 이 중 하나라도 달라지면 기존
승인은 무효가 되고 재승인을 요구한다. 따라서 승인 이후 `PATH`를 바꿔 다른 바이너리를
실행시키는 우회는 성립하지 않는다.

승인 기록 위치는 저장소 **바깥**이며 기본값은 `~/.unlazy/approved`다. 저장소 안을
가리키도록 설정하면 거부한다.

## 4. 네트워크 통신

**없다.** 배포 코드 어디에도 네트워크 API가 존재하지 않는다. 텔레메트리, 사용 통계,
외부 전송이 모두 없다.

확인 방법:

```bash
grep -rnE "node:(http|https|net|dgram|tls|http2)|fetch\(|WebSocket|XMLHttpRequest" scripts/ checks/
# 출력 없음
```

단, 사용자가 작성한 검증 명령 자체는 임의의 프로그램이므로 네트워크를 쓸 수 있다.
이는 도구의 통신이 아니라 사용자가 승인한 명령의 통신이며, 검토 대상은 원장의
`CHECK:` 문장이다.

## 5. 파일시스템 쓰기 범위

| 경로 | 쓰는 주체 | 시점 |
|---|---|---|
| `<저장소>/GATES.md`, `.unlazy/**` | 체커 | 게이트 실행 결과 기록 |
| `<저장소>/.unlazy-hook-state.json` | Stop 훅 | 세션 진행 상태 |
| `~/.unlazy/approved/*.json` | 체커 | `--approve` 시 승인 기록 |
| `.claude/settings.local.json` | 훅 설치기 | 사용자가 설치 명령을 실행할 때만 |
| `~/.claude/UNLAZY-BRIDGE.md` | 브리지 설치기 | 사용자가 설치 명령을 실행할 때만 |

문서·데이터 검증기 6종(`checks/`)은 **파일을 전혀 쓰지 않는 순수 읽기 도구**다.
감사 익스포트도 `--out`으로 지정한 파일 외에는 아무것도 쓰지 않는다.

확인 방법:

```bash
grep -c "writeFileSync\|appendFileSync\|mkdirSync\|unlinkSync" checks/check-*.mjs checks/lib/*.mjs
# 전부 0
```

설정 파일을 수정할 때는 원자적으로 쓰고 `<파일>.unlazy.bak` 백업을 남기며, 다른
도구가 등록한 항목은 보존한다.

## 6. 데이터 취급과 잔존

성공한 검증 명령의 **출력 원문은 저장하지 않는다.** 원장에 남는 것은 종료 코드,
해석된 셸과 작업 디렉터리, `PATH` 지문(해시), 기대 문자열 일치 여부, 그리고 출력의
SHA-256 해시와 바이트 수뿐이다.

따라서 검증 대상에 고객 정보나 계좌 정보가 포함되어 있더라도 그 내용이 원장이나 감사
자료에 복사되지 않는다. 실패 시에만 진단을 위해 제한된 분량의 출력 일부가 터미널에
표시되며, 이 역시 파일에 저장되지 않는다.

감사 익스포트는 기본적으로 승인에 묶인 `PATH`를 해시로만 기록한다. `PATH`에 계정명과
설치 소프트웨어가 드러나기 때문이다.

## 7. 인증정보 취급

도구는 인증정보를 요구하지도, 저장하지도, 읽지도 않는다. 자격 증명 저장소나 브라우저
세션에 접근하지 않는다.

검증 명령이 자격 증명을 사용하도록 사용자가 작성할 수는 있으므로, `CHECK:` 문장에
비밀번호나 토큰을 직접 적지 않는 것을 사내 작성 규칙으로 둔다. 승인 기록에 명령
문자열이 그대로 보관되기 때문이다.

## 8. 알려진 제약과 잔존 위험

과장 없이 밝힌다. 아래는 이 도구가 **방어하지 않는다고 스스로 선언한** 영역이다.

1. **샌드박스가 아니다.** 안전 경계는 사람의 검토와 명시적 승인이지 격리가 아니다.
   승인된 명령은 실행 계정의 권한으로 파일시스템·환경변수·네트워크에 접근한다.
   실질적으로 "사용자가 터미널에 직접 입력하는 명령"과 같은 수준의 권한이다.
2. **승인은 호출된 스크립트의 바이트를 고정하지 않는다.** 명령 텍스트가 같으면 그
   명령이 실행하는 파일이 교체되어도 기존 승인이 유효하다. 완화책은 기대 해시를
   `CHECK:` 문장에 직접 포함시켜 승인 서명에 묶는 것이다.
3. **Windows에서 승인 저장소 권한이 검증되지 않는다.** 엔진이 소유자·권한 검사를
   win32에서 건너뛰므로 NTFS ACL에 의존한다. 다중 사용자 단말이나 터미널 서버에서는
   9절의 통제를 적용한다.
4. **Windows 타임아웃 정리가 완전하지 않을 수 있다.** `taskkill` 보조 실행이 실패하면
   직접 자식만 종료되고 손자 프로세스가 남을 수 있다. 진단 메시지로 보고된다.
5. **소유권 리스(lease)는 격리가 아니다.** 병렬 작업 간 조정 장치일 뿐이며 프로토콜을
   무시하는 프로세스의 쓰기를 막지 못한다.
6. **환경변수 전체가 상속된다.** 승인은 `PATH`에는 묶이지만 `NODE_OPTIONS` 같은 다른
   코드 주입 변수에는 묶이지 않는다.

## 9. 권고 운영 통제

| 통제 | 내용 |
|---|---|
| 설치 경로 고정 | 사내 표준 경로에 배포하고 사용자별 임의 설치를 금지 |
| 셸 표준화 | `UNLAZY_SHELL`을 시스템 환경변수로 고정. 승인이 셸 절대경로에 묶이므로 셸 통일이 곧 승인 재사용성과 재검증 일관성 |
| 승인 저장소 보호 | Windows에서 `%USERPROFILE%\.unlazy`에 상속 제거 후 현재 사용자 단독 권한을 부여(`icacls`). 8절 3항 완화 |
| 검증기 무결성 | 사내 배포 검증 스크립트는 기대 해시를 `CHECK:` 문장에 포함해 승인 서명에 묶기 |
| 원장 검토 | `CHECK:` 문장은 코드로 취급. 신뢰할 수 없는 출처의 원장은 `--status`로 먼저 읽고 승인 |
| 훅 설치 | 팀 공유 설정(`--shared`)은 절대경로가 박히므로 표준 이미지 사용 팀에만 허용 |
| 반입 검증 | 반입 후 `npm test` 1회 실행으로 무결성 확인 |

## 10. 중단 및 철회 경로

강제 계층이 사용자를 가두지 않도록 해제 경로가 다중으로 존재한다.

1. 세션 종료 차단은 진전 없이 6회 연속 차단되면 자동 해제된다.
2. 불가능해진 기준은 `ABANDON:` 선언으로 사유를 남기고 종료할 수 있다.
3. 훅은 `install-hooks.mjs --uninstall`로 제거한다.
4. `.unlazy/` 디렉터리를 삭제하면 강제 대상 자체가 사라진다.
5. 도구 전체 제거는 설치 디렉터리 삭제로 끝난다. 레지스트리나 서비스 등록이 없다.

## 11. 보안팀 자체 점검 체크리스트

```bash
# 1) 외부 의존성 없음
grep -E '"dependencies"' package.json ; ls node_modules

# 2) 네트워크 코드 없음
grep -rnE "node:(http|https|net|dgram|tls)|fetch\(|WebSocket" scripts/ checks/

# 3) 프로세스 실행 가능 파일이 3개뿐임
grep -rn "child_process" scripts/ checks/ | grep -v tests

# 4) 검증기가 파일을 쓰지 않음
grep -c "writeFileSync\|appendFileSync" checks/check-*.mjs checks/lib/*.mjs

# 5) 3.2절 실행 경계 실증(양성 대조 포함)

# 6) 오프라인 전량 테스트
npm test
```

## 12. 미확인 항목

이 문서가 확인하지 않은 것을 밝힌다.

- 사내 표준 단말의 백신·EDR·DLP가 Node 프로세스 생성, `taskkill` 호출,
  `%USERPROFILE%\.unlazy` 쓰기를 간섭하는지 여부.
- VDI 또는 프로파일 초기화 정책이 적용된 환경에서 승인 저장소가 유지되는지 여부.
- 상용 환경에서의 성능 영향.

세 항목은 사내 표준 이미지에서의 시범 적용으로 확인이 필요하다.
